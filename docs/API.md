# Transaction Ledger API – Reference

Base URL (local): `http://localhost:8000`
Interactive documentation: `/docs` (Swagger UI) · `/redoc` · raw spec `/openapi.json` (a copy is in [`openapi.json`](openapi.json)).

All requests and responses are JSON (`Content-Type: application/json`).

## Conventions

| Topic | Convention |
| --- | --- |
| Identifiers | `id`, `account_id`, `transaction_id`, `transfer_id` are server-generated UUID strings. |
| Money | **Input:** JSON number or numeric string, `> 0`, at most 2 decimal places (`100`, `"12.50"`, `0.1`). **Output:** always a string with exactly two decimals (`"100.00"`). Stored internally as exact integer minor units. |
| Timestamps | `created_at` is generated by the server, UTC, ISO‑8601 with `Z` suffix and microsecond precision, e.g. `2026-10-27T09:15:00.123456Z`. |
| Unknown fields | Request bodies reject unknown fields (`400 VALIDATION_ERROR`). This is what prevents a client from setting `balance`, `id` or `created_at`. |
| Whitespace | String fields are trimmed; blank strings count as missing. |
| Errors | One envelope for every error – see [Errors](#errors). |

## Accounts

### Create account

`POST /accounts`

| Body field | Type | Rules |
| --- | --- | --- |
| `name` | string | required, non-blank, ≤ 100 characters |

The balance always starts at `0.00`; `id` and `created_at` are generated by the server.

```bash
curl -X POST http://localhost:8000/accounts \
     -H 'Content-Type: application/json' \
     -d '{"name": "Alice Sharma"}'
```

`201 Created`

```json
{
  "id": "7a3f2a3e-5e4c-4b3a-9d2f-1c2b3a4d5e6f",
  "name": "Alice Sharma",
  "balance": "0.00",
  "created_at": "2026-10-27T09:15:00.123456Z"
}
```

| Status | Code | When |
| --- | --- | --- |
| `400` | `VALIDATION_ERROR` | `name` missing/blank/not a string, or unknown fields such as `balance` supplied |

Example – client tries to set the balance:

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "The request is invalid. See 'details.fields' for the individual problems.",
    "details": {
      "fields": [
        { "field": "body.balance", "message": "Extra inputs are not permitted", "type": "extra_forbidden" }
      ]
    }
  }
}
```

### Get account

`GET /accounts/{account_id}` → `200` with the same shape as the create response. `404 ACCOUNT_NOT_FOUND` if unknown.

### Get account balance

`GET /accounts/{account_id}/balance`

```bash
curl http://localhost:8000/accounts/7a3f2a3e-5e4c-4b3a-9d2f-1c2b3a4d5e6f/balance
```

`200 OK`

```json
{
  "account_id": "7a3f2a3e-5e4c-4b3a-9d2f-1c2b3a4d5e6f",
  "name": "Alice Sharma",
  "balance": "150.00"
}
```

| Status | Code | When |
| --- | --- | --- |
| `404` | `ACCOUNT_NOT_FOUND` | Unknown `account_id` |

## Transactions

### Add transaction

`POST /accounts/{account_id}/transactions`

| Body field | Type | Rules |
| --- | --- | --- |
| `type` | string | required, exactly `credit` or `debit` (lowercase) |
| `amount` | number or string | required, `> 0`, ≤ 2 decimal places, ≤ 15 digits |
| `reference_id` | string | required, non-blank, ≤ 100 characters, **unique per account** (idempotency key) |
| `description` | string | optional, ≤ 500 characters |

Behaviour:

* `credit` increases the balance by `amount`; `debit` decreases it.
* A `debit` greater than the current balance is rejected with `422 INSUFFICIENT_BALANCE`; nothing is recorded and the balance does not change.
* Re-submitting a `reference_id` already used on this account returns `409 DUPLICATE_TRANSACTION`; no new transaction is created, the balance does not change and the original transaction is returned in `details.existing_transaction`. The same `reference_id` may be used on other accounts.
* Creating the transaction and updating the balance happen in one atomic database transaction.
* Transactions are immutable – there is no way to edit or delete them (`405 METHOD_NOT_ALLOWED`).

```bash
curl -X POST http://localhost:8000/accounts/7a3f2a3e-5e4c-4b3a-9d2f-1c2b3a4d5e6f/transactions \
     -H 'Content-Type: application/json' \
     -d '{"type": "credit", "amount": 50, "description": "Bonus", "reference_id": "BON-2026-001"}'
```

`201 Created`

```json
{
  "id": "0ac2f0d0-01ff-44fc-99d9-a4210ebef83e",
  "account_id": "7a3f2a3e-5e4c-4b3a-9d2f-1c2b3a4d5e6f",
  "type": "credit",
  "amount": "50.00",
  "description": "Bonus",
  "reference_id": "BON-2026-001",
  "transfer_id": null,
  "created_at": "2026-10-27T09:16:30.654321Z",
  "balance_after": "150.00"
}
```

`balance_after` is the account balance immediately after this transaction was applied. `transfer_id` is set only when the transaction is one leg of a transfer.

| Status | Code | When |
| --- | --- | --- |
| `400` | `VALIDATION_ERROR` | invalid/missing `type`, `amount`, `reference_id`; unknown fields; malformed JSON |
| `404` | `ACCOUNT_NOT_FOUND` | unknown `account_id` |
| `409` | `DUPLICATE_TRANSACTION` | `reference_id` already used for this account |
| `422` | `INSUFFICIENT_BALANCE` | debit larger than the current balance |

Insufficient balance example (balance 100, debit 150):

```json
{
  "error": {
    "code": "INSUFFICIENT_BALANCE",
    "message": "Insufficient balance: account '7a3f2a3e-…' has 100.00 but 150.00 was requested. The transaction was rejected and the balance is unchanged.",
    "details": { "account_id": "7a3f2a3e-…", "balance": "100.00", "requested_amount": "150.00" }
  }
}
```

Duplicate example:

```json
{
  "error": {
    "code": "DUPLICATE_TRANSACTION",
    "message": "A transaction with reference_id 'BON-2026-001' already exists for account '7a3f2a3e-…'. No new transaction was created and the balance is unchanged.",
    "details": {
      "account_id": "7a3f2a3e-…",
      "reference_id": "BON-2026-001",
      "existing_transaction": {
        "id": "0ac2f0d0-01ff-44fc-99d9-a4210ebef83e",
        "account_id": "7a3f2a3e-…",
        "type": "credit",
        "amount": "50.00",
        "description": "Bonus",
        "reference_id": "BON-2026-001",
        "transfer_id": null,
        "created_at": "2026-10-27T09:16:30.654321Z"
      }
    }
  }
}
```

### Add transaction (account id in body)

`POST /transactions` – identical behaviour; the body additionally contains `account_id`.

```json
{ "account_id": "7a3f2a3e-…", "type": "debit", "amount": "30.00", "reference_id": "GRO-001", "description": "Groceries" }
```

### Get a transaction

`GET /transactions/{transaction_id}` → `200` with the transaction (without `balance_after`). `404 TRANSACTION_NOT_FOUND` if unknown.

### Modify / delete a transaction

`PUT`, `PATCH`, `DELETE` on `/transactions/{transaction_id}` or `/accounts/{account_id}/transactions` → `405 METHOD_NOT_ALLOWED`:

```json
{
  "error": {
    "code": "METHOD_NOT_ALLOWED",
    "message": "Method DELETE is not allowed on /transactions/0ac2f0d0-…. Transactions are immutable: they cannot be edited or deleted."
  }
}
```

## Transaction history

`GET /accounts/{account_id}/transactions`

| Query parameter | Type | Default | Rules |
| --- | --- | --- | --- |
| `type` | string | – (both) | `credit` or `debit` |
| `page` | integer | `1` | ≥ 1 |
| `limit` | integer | `20` | 1 … 100 |

Transactions are returned **latest first** (by `created_at`, ties broken by insertion order).

```bash
curl "http://localhost:8000/accounts/7a3f2a3e-5e4c-4b3a-9d2f-1c2b3a4d5e6f/transactions?type=debit&page=1&limit=2"
```

`200 OK`

```json
{
  "data": [
    {
      "id": "8c3dd439-6fa5-4025-a694-93f1ca5e149b",
      "account_id": "7a3f2a3e-5e4c-4b3a-9d2f-1c2b3a4d5e6f",
      "type": "debit",
      "amount": "20.00",
      "description": "Fuel",
      "reference_id": "FUEL-001",
      "transfer_id": null,
      "created_at": "2026-10-27T09:20:11.000001Z"
    },
    {
      "id": "7d1308bf-1a3e-4014-99e1-ef96484894f6",
      "account_id": "7a3f2a3e-5e4c-4b3a-9d2f-1c2b3a4d5e6f",
      "type": "debit",
      "amount": "30.00",
      "description": "Groceries",
      "reference_id": "GRO-001",
      "transfer_id": null,
      "created_at": "2026-10-27T09:18:05.000001Z"
    }
  ],
  "pagination": {
    "page": 1,
    "limit": 2,
    "total_records": 5,
    "total_pages": 3,
    "has_next": true,
    "has_previous": false
  }
}
```

`total_records` / `total_pages` respect the `type` filter. Requesting a page beyond the last one returns an empty `data` array with the metadata (not an error). An account with no transactions returns `total_pages: 0`.

| Status | Code | When |
| --- | --- | --- |
| `400` | `VALIDATION_ERROR` | `type` not `credit`/`debit`; `page < 1`; `limit` outside 1–100; non-integer values |
| `404` | `ACCOUNT_NOT_FOUND` | unknown `account_id` |

## Transfers (bonus)

### Create transfer

`POST /transfers`

| Body field | Type | Rules |
| --- | --- | --- |
| `from_account_id` | string | required – account to debit |
| `to_account_id` | string | required – account to credit, must differ from `from_account_id` |
| `amount` | number or string | required, `> 0`, ≤ 2 decimal places |
| `description` | string | optional, ≤ 500 characters; used for both legs |
| `reference_id` | string | optional idempotency key, applied to **both** legs (unique per account). Server generates `TRF-<uuid>` when omitted. |

The debit on the source, the credit on the destination and the transfer record are written in **one atomic database transaction**. If any part fails (insufficient balance, unknown account, duplicate reference, constraint violation, unexpected error) nothing is persisted – a partial transfer is impossible.

```bash
curl -X POST http://localhost:8000/transfers \
     -H 'Content-Type: application/json' \
     -d '{"from_account_id": "7a3f2a3e-…", "to_account_id": "64883222-…", "amount": 30, "description": "Rent share", "reference_id": "TRF-001"}'
```

`201 Created` (Alice had 100, Bob had 50):

```json
{
  "id": "e5807cc1-619c-4784-911d-cd5cbcc752b1",
  "from_account_id": "7a3f2a3e-…",
  "to_account_id": "64883222-…",
  "amount": "30.00",
  "description": "Rent share",
  "reference_id": "TRF-001",
  "debit_transaction": {
    "id": "777b2b35-c053-4fe1-aaba-d19f8580f757",
    "account_id": "7a3f2a3e-…",
    "type": "debit",
    "amount": "30.00",
    "description": "Rent share",
    "reference_id": "TRF-001",
    "transfer_id": "e5807cc1-619c-4784-911d-cd5cbcc752b1",
    "created_at": "2026-10-27T09:25:00.000001Z"
  },
  "credit_transaction": {
    "id": "a1b2c3d4-0000-4000-8000-000000000001",
    "account_id": "64883222-…",
    "type": "credit",
    "amount": "30.00",
    "description": "Rent share",
    "reference_id": "TRF-001",
    "transfer_id": "e5807cc1-619c-4784-911d-cd5cbcc752b1",
    "created_at": "2026-10-27T09:25:00.000001Z"
  },
  "from_account_balance": "70.00",
  "to_account_balance": "80.00",
  "created_at": "2026-10-27T09:25:00.000001Z"
}
```

| Status | Code | When |
| --- | --- | --- |
| `400` | `VALIDATION_ERROR` | missing/invalid fields |
| `404` | `ACCOUNT_NOT_FOUND` | source or destination unknown (message says which) |
| `409` | `DUPLICATE_TRANSACTION` | `reference_id` already used on the source or destination account |
| `422` | `INSUFFICIENT_BALANCE` | source balance lower than `amount` |
| `422` | `SAME_ACCOUNT_TRANSFER` | `from_account_id == to_account_id` |

### Get transfer

`GET /transfers/{transfer_id}` → `200` with the same shape (balances reflect the *current* account balances). `404 TRANSFER_NOT_FOUND` if unknown.

## Errors

Every error response has this shape:

```json
{
  "error": {
    "code": "MACHINE_READABLE_CODE",
    "message": "Human readable explanation.",
    "details": { "...": "optional, machine readable context" }
  }
}
```

| HTTP | `code` | `details` |
| --- | --- | --- |
| `400` | `VALIDATION_ERROR` | `{"fields": [{"field": "body.amount", "message": "…", "type": "…"}, …]}` – one entry per problem; `field` is the location (`body.x`, `query.x`, `path.x`, or `body` for malformed JSON) |
| `404` | `ACCOUNT_NOT_FOUND` | `{"account_id": "…"}` |
| `404` | `TRANSACTION_NOT_FOUND` | `{"transaction_id": "…"}` |
| `404` | `TRANSFER_NOT_FOUND` | `{"transfer_id": "…"}` |
| `404` | `NOT_FOUND` | – (unknown route) |
| `405` | `METHOD_NOT_ALLOWED` | – |
| `409` | `DUPLICATE_TRANSACTION` | `{"account_id", "reference_id", "existing_transaction": {…}}` |
| `422` | `INSUFFICIENT_BALANCE` | `{"account_id", "balance", "requested_amount"}` |
| `422` | `SAME_ACCOUNT_TRANSFER` | `{"account_id"}` |
| `500` | `INTERNAL_ERROR` | – (nothing was persisted) |

Status-code philosophy: `400` for requests that are malformed or fail schema validation, `404` for unknown resources, `409` for idempotency conflicts, `422` for well-formed requests that violate a business rule, `405` for attempts to mutate immutable resources.
